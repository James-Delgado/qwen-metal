# benchmarks/phase6/ — raw exports of record for the Phase 6 round

Every Phase 6 headline number is regenerated by `tools/phase6_analyze.py`
from the files in this directory (docs/phases/phase-6.md D8; METHODOLOGY 4).
Nothing here is edited after archival; results.md keeps the dated rows as
the human ledger and cites these files. Layout decided at P6-3 (agent,
reversible, convention-following — surfaced in the P6-3 report).

```
benchmarks/phase6/
  README.md              this file
  manifest.json          operator-typed session facts (schema below)
  speed/                 P6-4 speed session (one calendar session, one iOS build)
    <engine>-<kind>-<n>.txt      text export of record (Copy export)
    <engine>-<kind>-<n>.json     timeline JSON, same stem (Copy JSON)
    bandwidth-<kernel>-<n>.txt   bandwidth microbench exports (weights-free)
  energy/                P6-5 energy round (same iOS build as speed/)
    <engine>-energy-<n>.txt / .json
```

## File naming

`<engine>` ∈ `ours` | `mlx` | `llama`. `<kind>` names the row the operator
intended; the analyzer trusts the export CONTENT for engine, mode, prompt
and cold/warm, and reads only two things from the file name:

| stem pattern | meaning |
|---|---|
| `ours-bookend-open`, `ours-bookend-close` | our warm-burst bookends (they also count as warm decode rows) |
| `bandwidth-triad-<n>`, `bandwidth-readonly-<n>` | the bandwidth pair; equal `<n>` = one interleaved pair (paired ratio) |

Recommended kinds otherwise: `decode-cold`, `decode-warm`, `prefill-cold`,
`prefill-warm`, `sustained`, `energy`. Anything that parses as a row export
is classified from its content: `mode: burst` + `decode-essay` ⇒ decode
row; `mode: burst` + `prefill-summarize` ⇒ prefill row; a loop export in
`speed/` ⇒ the 5-min sustained row; a loop export in `energy/` ⇒ an energy
cycle. One text file per row, its JSON timeline next to it with the same
stem (required for the thermal chart's loop-clock x-axis on our rows; the
external text exports carry `[elapsed …]` on every gen line).

Attribution exports (DIAGNOSTIC — never rows) go in `speed/attribution/`
and are ignored by the analyzer; the writeup's section 6 quotes them
directly.

## manifest.json

The external harness exports carry no device/iOS line and the Xcode memory
gauge is read by eye, so those facts are typed here once per session. The
analyzer REFUSES any headline that depends on a missing field.

```json
{
  "device": "iPhone16,1 (iPhone 15 Pro)",
  "engine_build": {"tag": "phase6-build", "commit": "<sha of the tagged commit>"},
  "sessions": {
    "speed": {
      "round": "phase6-speed-2026-10-01",
      "dir": "speed",
      "date": "2026-10-01",
      "ios_build": "26.6.1",
      "xcode": "26.6 (17F113)",
      "footprint_mb": {"ours-mmap": 0.0, "ours-wired": 0.0, "mlx": 0.0, "llama": 0.0},
      "footprint_note": "Xcode memory gauge, attached footprint-only launches after the timed rows"
    },
    "energy": {
      "round": "phase6-energy-2026-10-04",
      "dir": "energy",
      "date": "2026-10-04",
      "ios_build": "26.6.1",
      "idle_baseline": {
        "health_percent": 100, "soc_start": 80, "soc_end": 76,
        "wall_seconds": 3600, "ios_build": "26.6.1",
        "note": "app foregrounded, no generation, airplane mode, min brightness, ≥4% SoC drop"
      }
    }
  },
  "roofline": {"weight_bytes": {"mlx": 0, "llama": 0}}
}
```

- `round` must equal the round marker typed into each app for that session
  (an export whose `round:` line disagrees, or which is PROVISIONAL, is not
  a headline row).
- `ios_build` must match the `device: … (iOS …)` line of every export of
  ours in that session, and the energy round's must equal the speed
  session's — the D7 same-build rule.
- `idle_baseline` is the D4 idle run (once per iOS build; ≥4% SoC drop or
  the analyzer refuses every energy headline).
- `roofline.weight_bytes` is optional: per-engine weight bytes streamed per
  token, if the writeup wants implied-bandwidth rows for the external
  engines (ours is built in: 967,753,728 B).
- `operator_overrides` (optional, per session; added at P6-4 by James's
  decision): fields the operator supplies post hoc for exports that were
  copied before the app fields were typed — `defaults` (`round`,
  `battery_health_percent`) applied to every row of the session whose
  export left the field blank, and `rows.<stem>` (`cold_warm`, or the same
  two) per file. Only BLANK fields are filled: an export's own value always
  wins, so an export whose own round line disagrees with the session is
  still refused. Every filled field is labeled "operator-supplied post hoc"
  in the analyzer's notes and the refusal ledger, and the export text is
  never edited. Record the decision in DECISIONS.md whenever this block is
  used.

## Regenerating the writeup tables and figures

```sh
.venv/bin/pip install -r tools/requirements-phase6.txt   # once
.venv/bin/python tools/phase6_analyze.py benchmarks/phase6 --out docs/writeup
```

Writes `docs/writeup/tables.md`, `summary.json`, `thermal.png`, `energy.png`.
Tests: `.venv/bin/python -m pytest tests/test_phase6_analyze.py -q`.
